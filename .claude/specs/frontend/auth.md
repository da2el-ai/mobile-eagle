## 3. 起動フロー

```
アプリ起動（App マウント）
  ├─ GET /api/auth/check
  │    ├─ authRequired: false または authenticated: true
  │    │    → 通常の初期化（フォルダ・一覧のロード）へ
  │    └─ authRequired: true かつ authenticated: false
  │         → 認証ダイアログを表示。データのロードは一切行わない
  │              └─ ログイン成功 → ダイアログを閉じて通常の初期化へ
  └─ check 自体が失敗（サーバー停止等） → status: 'error'（認証ダイアログは出さない）
```

- 認証状態は `auth` store（`status: 'checking' | 'required' | 'ok' | 'error'`）で持つ。
  `status !== 'ok'` の間はルート watch・自動リロードを起動しない
- `'error'` のときは画面中央に「サーバーに接続できません」と**再試行ボタン**を表示する
  （再試行で check からやり直す。白画面のまま固まらせない）

## 4. ダイアログ UI

フィルタ・設定と同じモーダル枠（上寄せ・max-width 480px）。**z-index 95**（最前面。base.md 5.2）。

| 要素 | 内容 |
| --- | --- |
| タイトル | 「認証」（閉じるボタンは**置かない**） |
| パスワード入力 | `type="password"`（`*` で不可視）。placeholder「パスワードを入力」。`font-size: 16px` 以上。Enter キーで送信 |
| エラーメッセージ | 入力欄の下に赤（`#e2554b`）で表示。入力を変更したら消す |
| OK ボタン | `--accent`。タップで `POST /api/auth/login` |

- **背景クリック・Esc では閉じない**（認証されるまでアプリを操作させない）
- 送信中は OK ボタンを無効化（`opacity: 0.5`）
- 失敗（401）: エラーメッセージ「パスワードが間違っています」を表示し、入力は保持。
  **文言は `locales/` のキーを使う**（サーバーの `message` は表示に使わない。
  英語 UI に日本語が混ざるのを防ぐ）
- 成功: ダイアログを閉じ、起動フロー（3 章）の初期化を続行する

## 5. 401 ハンドリング（セッション失効）

- API クライアント（base.md 9 章）は **401 レスポンスを共通処理**する:
  `auth` store を `required` に戻し、認証ダイアログを再表示する
  （パスワード変更などで Cookie が無効化されたケース）
- **`/api/auth/*`（check / login）は 401 共通処理の対象外**とする
  （login の誤パスワード 401 はダイアログ内エラー表示で処理する。二重処理・ループを防ぐ）
- 再ログイン成功後は**アプリを初期化し直す**（フォルダ再取得 + 現在の route で
  `loadFirstPage()`）。失敗したリクエストの個別リトライはしない（実装を単純に保つ）。
  自動リロードの**基準シグネチャもリセット**する（初回チェック扱い。grid.md 6.2。
  古い基準と比較して復帰直後に余分なリロードが走るのを防ぐ）
- ダイアログ表示中に自動リロードのタイマーは停止する（grid.md 6.2 の停止条件に含める）

## 6. エッジケース

| ケース | 挙動 |
| --- | --- |
| localhost（Vite dev プロキシ）からのアクセス | `authRequired: false` のためダイアログは出ない（backend/auth.md 4 章） |
| パスワード未設定 | 同上（ダイアログは出ない） |
| 認証中にブラウザバック等で URL が変わる | `status !== 'ok'` の間はルート watch を起動しないため何も起きない。認証後に現在の URL で初期化 |
| 複数タブ | Cookie は共有されるため、片方でログインすれば他方もリロードで通る |
