# ライブラリの強制再読み込み（フロントエンド） 仕様書

## 1. 概要

設定ダイアログの最下部に「ライブラリを再読み込み」ボタンを置き、
実行中はスピナーと経過時間のダイアログを表示する。完了は 5 秒間隔のポーリングで検知し、
完了したらダイアログを閉じてトーストを出し、一覧とフォルダを読み直す。

## 2. 背景・目的

処理の本体と背景は [backend/library-reload.md](../backend/library-reload.md)。
再構築には数分かかり（2.6 万件で約 4 分 20 秒）、Eagle の画面が手元に無いと進み具合が分からない。
スマホ側で「実行中であること」と「経過時間」を見せ、終わったら自動で最新の状態に戻す。

## 4. 機能要件

### 4.1 実行の流れ

1. 設定ダイアログの「ライブラリを再読み込み」ボタンをタップ
2. `window.confirm` で確認する（ライトボックスの削除確認と同じ方式）
3. OK なら設定ダイアログを閉じ、実行中ダイアログを開いて `POST /reload_library` を送る
4. **POST の応答も、ポーリングの応答と同じく 4.2 の表で処理する**（通常は `running`。
   開始処理はサーバー側で応答後に進むため、その失敗は後続のポーリングで `error` として届く）
5. 以後 **5 秒間隔**で `GET /reload_library_status` をポーリングする

### 4.2 受け取った状態ごとの処理

| state | 挙動 |
| --- | --- |
| `running` | 表示を続ける。経過時間の基準を更新する（4.4） |
| `done` | ダイアログを閉じ、トースト「ライブラリの再読み込みが完了しました」。一覧とフォルダを読み直す（4.5） |
| `timeout` / `error` | スピナーを消し、ダイアログ内にエラー（9 章）と閉じるボタンを出す（トーストではなく残す） |
| `idle` | 実行中にプラグインが再起動された。エラー表示にする（9 章） |

### 4.3 復帰チェック

- **認証 OK になるたびに**（起動時・再ログイン後とも）`GET /reload_library_status` を 1 回呼び、
  `running` なら実行中ダイアログを開いてポーリングを始める
- `done` / `timeout` / `error` / `idle` のときは何もしない（過去の結果を蒸し返さない）
- すでにダイアログが開いていてポーリング中なら、**タイマーを張り直さない**（冪等にする）
- これにより、ブラウザのリロード・タブの破棄・401 からの再ログイン・別端末からの実行でも状態が見える

### 4.4 経過時間

- 表示形式は `m:ss`（例：`4:20`）。15 分でタイムアウトするため 1 時間を超えることはない
- **表示値 ＝ 最後に受け取った `elapsedMs` ＋（今 − 受け取った時刻）** で計算し、1 秒ごとに再描画する
  - 1 秒ごとに加算する方式にしない。バックグラウンドのタブではタイマーが止まる・間引かれるため、ずれる
  - サーバーの値を基準にするので、ページを開き直しても正しい経過時間から始まり、端末の時計にも依存しない

### 4.5 完了時の読み直し

- 読み直しは**自動リロード（`use-auto-reload.ts`）に依頼する**。スクロール位置の保持（grid.md 6.3）と
  基準シグネチャはそちらが持っているため
- ストアの `completedSeq`（完了のたびに 1 増える数値）を自動リロード側が watch し、変化したら
  1. 基準シグネチャを捨てる（読み直し後に再度「変化あり」と誤判定して 2 回目の読み直しが走るのを防ぐ）
  2. スクロール位置を保持して `items.reloadAll()` と `folders.load()` を実行する
- この読み直しは**自動更新の設定が OFF でも行う**（ユーザーが明示的に実行した操作の結果のため）
- ただし、選択モード中・Lightbox 表示中・一覧ロード中は、今の自動リロードと同じ理由で実行できない。
  その場合は「読み直し待ち」の印を付け、これらの条件が外れた時点で 1 回実行する

### 4.6 実行中の他機能との関係

- **自動リロードのポーリングを止める**（grid.md 6.2 の停止条件に「ライブラリ再読み込み中」を加える）。
  再構築中は古いデータが返るため、ポーリングしても意味がない
- 実行中ダイアログは閉じられない（`AppDialog` の `closable=false`）。背景の操作もできない
- **認証 OK でない間はポーリングを止める**。401 になると既存の共通処理で認証ダイアログに切り替わり、
  実行中ダイアログはアンマウントされる（他のダイアログと同じ場所に置くため。7.2）。
  再ログイン後は 4.3 の復帰チェックで実行中ダイアログに戻る

## 5. 実行環境

フロントエンド側のみ（ブラウザ）。プラグイン側との分界点は 2 つのエンドポイント（backend 6 章）。

## 6. HTTP エンドポイント

新規エンドポイントは backend 側で定義する。フロントエンドは [eagle-api.ts](../../../frontend/src/api/eagle-api.ts) に次を追加する。

- `startLibraryReload(): Promise<TLibraryReload>` — `POST /reload_library`
- `fetchLibraryReloadStatus(): Promise<TLibraryReload>` — `GET /reload_library_status`

どちらも既存の `requestJson` を通す（401 の共通処理に乗せる。auth.md 5 章）。
応答の `reload` キーの中身を返す。

## 7. UI 仕様

### 7.1 設定ダイアログ（最下部）

バージョン表記の**上**に、ほかの項目と同じ「見出し / 内容」の形で置く。

| 要素 | 内容 |
| --- | --- |
| 見出し | ライブラリ |

| 説明文（`--muted` 12px） | 「他の端末での変更が反映されないときに使います。完了まで数分かかります」 |

ボタンの見た目（塗りか枠線か）は、実装後に実機で見て決める（オープン課題）。

### 7.2 実行中ダイアログ（`LibraryReloadDialog.vue`）

- 枠は `AppDialog`（`closable=false`）。**z-index は 90**
  （Lightbox の部品は最大 88〔フィルムストリップ〕まであるためその上、認証 95 より下）
- マウント位置は `App.vue` の、既存ダイアログと同じ「認証 OK のときだけ描画する」ブロックの中（`v-if="store.isOpen"`）
- タイトル：「ライブラリを再読み込み中」
- 本文（中央寄せ、縦並び）

| 状態 | 表示 |
| --- | --- |
| 実行中 | スピナー（Tailwind の `animate-spin`、枠線で描く円。色は `--accent`）<br>経過時間 `m:ss`（大きめの数字）<br>説明「Eagle がライブラリを読み込み直しています。完了までそのままお待ちください」 |
| 失敗（`timeout` / `error` / `idle` / 通信） | スピナーを消し、エラーメッセージ（9 章）と「閉じる」ボタン |

- スピナーは新規部品を共通化せず、このダイアログ内に書く（今のところ使う場所が 1 つのため）

### 7.3 文言（i18n）

`ja.ts` / `en.ts` の両方に追加する。

- 設定ダイアログの見出し・ボタン・説明文は、既存の設定項目と同じく `settings.*` に置く

## 8. データ構造・Eagle API の利用

### 8.1 型（`types.ts`）

```ts
export type TLibraryReloadState = 'idle' | 'running' | 'done' | 'timeout' | 'error';
export type TLibraryReloadReason =
  | 'busy'
  | 'delete_failed'
  | 'switch_failed'
  | 'not_rebuilt'
  | 'library_changed'
  | 'timeout';

export interface TLibraryReload {
  state: TLibraryReloadState;
  elapsedMs: number;
  timeoutMs: number;
  reason: TLibraryReloadReason | null;
}
```

### 8.2 状態の置き場所（Pinia ストア `stores/library-reload.ts`）

規約（coding.md 10 章「状態管理は Pinia」、base.md 8 章）に合わせて setup store にする。

- 状態
  - `isOpen`：実行中ダイアログを表示中
  - `phase`：`'running' | 'failed'`
  - `failure`：失敗時の種類（理由コード / `'idle'` / `'start_failed'` / `'unreachable'`）
  - `baseElapsedMs` / `baseReceivedAt`：経過時間の基準（4.4）
  - `completedSeq`：完了のたびに 1 増える（4.5 で自動リロード側が watch する）
- 関数：`start()`（開始。確認は呼び出し側の設定ダイアログで行い、OK なら設定ダイアログを閉じてから呼ぶ）/ `resume()`（4.3 の復帰チェック）/ `close()`（失敗時の閉じる）
- タイマー：ポーリング 5 秒（Mac では 2〜3 秒で完了するため）、表示更新 1 秒。ダイアログを閉じたとき・認証 OK でなくなったときに止める
- localStorage は使わない（状態はサーバーが持つ。4.3）

## 9. エッジケース・エラー処理

| ケース | 挙動 |
| --- | --- |
| `POST` が通信エラー・500 | **すぐに失敗にせず、`GET /reload_library_status` を 1 回確認する**（サーバー側では開始している可能性があるため）。`running` ならそのまま続行、それ以外・取得失敗なら「再読み込みを開始できませんでした」 |
| ポーリングが一時的に失敗（通信エラー） | 判定せず次回へ（ダイアログは実行中のまま）。自動リロードと同じ方針 |
| **最後にポーリングが成功してから** 16 分（タイムアウト 15 分＋余裕 1 分。定数で持つ）成功しない | 「状態を確認できませんでした」と閉じるボタン（サーバーに届かないまま永遠に回るのを防ぐ）。`timeoutMs` をまだ受け取っていない場合もあるため、サーバーの値ではなく定数を使う |
| `timeout` を受け取った | 「時間内に完了しませんでした。Eagle 本体のメニューから『キャッシュをクリアしてライブラリを再読み込み』を実行してください」 |
| `error` を受け取った | 理由コードごとの文言（`busy`：Eagle がライブラリを読み込み中です。しばらく待ってから実行してください。繰り返す場合は Eagle 本体のメニューから実行してください / `delete_failed`：キャッシュを削除できませんでした / `switch_failed`：ライブラリを開き直せませんでした / `not_rebuilt`：再読み込みされませんでした。もう一度実行してください / `library_changed`：実行中にライブラリが切り替わりました） |
| 実行中に `idle` を受け取った | 「プラグインが再起動されたため、状態が分からなくなりました」 |
| 401 | 既存の共通処理で認証ダイアログに切り替わる。ポーリングは止める（4.6）。再ログイン後に 4.3 で戻る |
| 別端末で実行中に、この端末でもボタンを押した | サーバーが既存の `running` を返すので、そのまま実行中ダイアログになる（二重実行されない） |
| タブが非表示の間 | タイマーは止めない（ブラウザが間引くだけ）。経過時間は 4.4 の計算なので、復帰時に正しい値に戻る |
| 完了時に選択モード中・Lightbox 表示中 | 読み直しを保留し、条件が外れたら 1 回実行する（4.5） |
