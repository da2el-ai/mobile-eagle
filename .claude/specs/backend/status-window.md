# ステータスウィンドウ 仕様書

## 1. 概要

プラグインの管理画面（ステータスウィンドウ）。普段は非表示で常駐し、ユーザーがプラグインパネルで
クリックしたときに表示する。サーバーの ON/OFF、ポート、アクセス用 QR コード、認証パスワードの設定と、
サーバー状態・ログの表示を担う。

**このウィンドウはプラグインのレンダラー内で完結し、HTTP を経由しない**（`eagle.*` API と
`ME.*` モジュールを直接呼ぶ）。スマートフォン側のフロントエンド（`frontend/`）とは別物。

## 2. 背景・目的

- `serviceMode: true` のプラグインは Eagle 起動時に自動常駐しウィンドウなしで動く（概要.md）。
  そのため、サーバーの状態確認・設定変更・初回アクセス（QR）のための最小限の管理 UI が要る。
- 現状の `plugin/index.html` は仮実装（ログを流すだけ）。本仕様でこれを置き換える。
- backend/base.md は「UI は別途仕様化」としてこの領域をスコープ外にしていた（同 11 章）。本仕様が
  その別仕様にあたる。

## 4. 機能要件

ウィンドウが持つ機能要素と、その振る舞い（状態・保存タイミング）を定義する。
**配置・寸法・配色などの見た目はモックアップに従い、本章では規定しない。**

### 4.1 サーバー ON/OFF トグル

- `ME.settings` の `serverEnabled` を切り替える。**トグル操作は即時反映**（保存ボタンでの確定は不要）
- ON: `ME.server.start(port)` を実行。OFF: `ME.server.stop()` を実行。結果を `serverEnabled` に保存する
- 起動失敗（ポート衝突など）時は 4.6 のエラー表示に従い、トグルは実際の稼働状態に合わせて戻す

### 4.2 ポート番号

- 数値入力。既定 `8000`。有効範囲は **1〜65535**（範囲外・非数は保存しない）
- **確定は共通の保存ボタン（4.8）**。稼働中にポートを変えたときの再起動挙動も 4.8 で定義する

### 4.3 アクセス用 QR コード + IP ドロップダウン

- **IP ドロップダウン**: `os.networkInterfaces()` で IPv4・非ループバックのアドレスを列挙する
  （`listIpAddresses()` のロジックを流用。ただし `label`（`detectKind()`）は捨て `address` のみ使う改変流用）。
  **ラベルによる種別区別（Tailscale / LAN 等）は付けず、IP アドレスをそのまま表示する**
  （ユーザー決定。流用元の `detectKind()` は使わない）
  - 選択値は**即時保存せず、共通の保存ボタン（4.8）で確定**する（保存時に `selectedIp` を保存し QR を再生成）
  - 起動時は保存済み `selectedIp` を復元する。該当が現存しなければ先頭を選ぶ
  - 1 件も見つからない場合は「（外部 IP が見つかりません）」等の非選択状態を表示する
    （文言はモックアップ/実装で調整。ここでは"選択肢なし"の状態が要る点のみ規定）
  - **Tailscale の `utun*` は起動直後に未出現のことがある**ため、起動時に 1 回で確定せず
    数秒おきに数回リトライしてから確定する（概要.md 78-79 / knowledge.md）
- **QR コード**: 選択中の IP とポートから `http://{ip}:{port}/` を組み立て、`qrcode` で画像化する
  （`QRCode.toDataURL()`。`generateQrCode()` を流用）。**スキームは `http` 固定**（VPN/LAN 前提）
  - IP 未選択・サーバー停止中でも URL は組めるが**到達不可**。状態表示（4.5）で稼働/停止を示す
  - **再生成は保存ボタン（4.8）押下時**（と起動時の初期表示時）。入力途中では更新しない
  - QR にはアクセス URL のみを載せる。**パスワード・認証トークンは絶対に含めない**（auth.md 4 章）
  - 停止中は QR を出さず、プレースホルダ表示にする（表示条件はオープン課題で詰める）
- **アクセス用 URL 表示**: `http://{selectedIp}:{port}/` を編集不可テキストとして表示し、
  クリックでクリップボードにコピーする（`navigator.clipboard.writeText`）。コピー後は一時的に
  「コピーしました」を示す。補助テキスト「クリックするとクリップボードにコピーされます」を添える

### 4.4 パスワード設定

- テキスト入力（`type=password`）。**目玉ボタンで可視（`text`）/不可視（`***`）を切り替える**。
  `ME.settings` の `password` に保存する
- 制約: **英数記号のみ・0〜128 文字**。空欄なら認証無効（auth.md 4 章の「空文字＝認証無効」）。
  補助テキスト「空欄にするとパスワード認証をしません。英数記号のみ最大128文字。」を添える
- **確定は共通の保存ボタン（4.8）**（テキスト入力のため、誤入力の即時反映を防ぐ）
- **認証ロジック本体・セッション無効化はこの仕様の担当外**。auth.md の決定的トークン方式
  （`SHA-256(password + 固定ソルト)`）により、**`password` を書き換えるだけで既存 Cookie は
  自動的に全端末で無効化**される（auth.md 7 章）。本仕様は「`password` を保存する」ところまで。
  `auth.js` がリクエストごとに `ME.settings` から読むため、保存が即反映される
- **auth.md がまだ未実装の段階**では、この項目は「設定値の保存」までを提供する
  （認証の実挙動確認は auth 実装後。それまで保存しても素通し）

### 4.5 サーバー状態表示

- ユーザーに示すのは**「起動成功／失敗」＝「稼働中／停止中」の事実のみ**。
  **エラーの詳細は画面に出さず、ログ（4.7）を参照させる**（画面内に詳細メッセージや
  `lastError` 相当の状態は持たない。ユーザー決定 2026-07-18）
- 状態文言（モックで確定。色分けはデザイン側）:
  - 稼働中: 「サーバー起動中」
  - 停止中: 「サーバー停止中」
  - 起動失敗: 「サーバーの起動に失敗。詳細はログをご覧ください。」
- 稼働中はアクセス先 `http://{selectedIp}:{port}/`（4.3 の URL 表示）も併せて示す（原因はログで確認）

### 4.6 エラー表示（重大エラー）

- **重大エラーのダイアログ（`eagle.window.show()` + `eagle.dialog.showMessageBox()`）は
  `ME.server`（server.js）が唯一の担当**。ポート使用中の起動失敗などは server.js が
  既に実施済み（概要.md 119-120）。
  **status-window.js は `start()` の reject を catch しても再度ダイアログを出さない**
  （同一エラーで 2 枚出るのを防ぐ）。status-window.js の責務は
  **稼働状態の復元**（トグル・状態表示を実態に戻す）と**起動成功/失敗の事実表示（4.5）**に留める
- 個別リクエストの失敗など**軽微なエラー**はログ（4.7）に記録するのみ（coding.md 9 章）

### 4.7 ログ表示

- `ME.logger` の直近 200 件を最新が先頭で表示する（既存 I/F: `getLines()` / `subscribe()`）
- `ME.logger.subscribe()` で更新を購読し、追記のたびに再描画する
- **ログクリア**操作を設ける（`ME.logger.clear()`）

### 4.8 設定の保存（IP・ポート・パスワード共通の保存ボタン）

- **IP ドロップダウン（4.3）・ポート番号（4.2）・パスワード（4.4）の 3 項目は入力しても即時反映せず、
  1 つの「保存」ボタンでまとめて確定する**（ユーザー決定 2026-07-18）。
  サーバー ON/OFF トグル（4.1）はこのボタンに含めず、従来どおり即時反映のまま
- 保存ボタン押下時の処理（この順序で行う）:
  1. 入力値を検証する（ポート 1〜65535 / パスワード 英数記号 0〜128 字）。
     不正な項目があれば保存せず、その項目を弾く（軽微・ログのみ）
  2. `ME.settings.set({ selectedIp, port, password })` でまとめて保存する
  3. **ポートが変わっていてサーバーが稼働中なら** `ME.server.stop()` →
     `ME.server.start(新ポート)` の順に再起動する（停止中なら保存のみ。次回 ON 時に反映）
  4. **QR コードを再生成する**（保存後の `selectedIp`・`port` で。4.3）
  5. パスワードを変更した場合、auth の既存 Cookie は自動的に無効化される（4.4 / auth.md 7 章）
- 再起動に失敗した場合のダイアログは server.js の担当（4.6）。稼働状態は実態に合わせる

### 4.9 常駐の注意書き・バージョン表記

- **サーバートグル（4.1）の直下**に次の注意書きを表示する（`--muted` 11px・中央寄せ）:
  「ウィンドウを閉じてもサーバーは終了しません。／サーバーを終了するには上のスイッチで停止させてください。」
  `manifest.json` の `serviceMode: true` によりウィンドウを閉じてもサーバーは常駐し続けるため、
  **停止方法をユーザーが誤解しないよう明示する**
- **ウィンドウ最下部**に `v{version}` を表示する。値は `ME.version`（`plugin/js/version.js`）が
  `manifest.json` から読む（単一ソース。base.md 6 章。ソースにハードコードしない）。
  読み取れなかった場合は「v」だけを出さず**無表示**にする
- バージョンは常時見える必要がないため**画面下部への固定はしない**（`body` の `display: flex` を外し、
  内容の直後に流す）。あわせてログ領域（4.7）は `max-height: 300px` とする

## 5. 実行環境

**プラグイン側のレンダラー**（`plugin/index.html` + `plugin/js/*.js`）。
Node.js（`os` / `require('qrcode')`）・DOM・`eagle.*` API のすべてが使える環境。

- ライフサイクル結線は既存の `plugin/js/main.js`（`onPluginCreate` / `onPluginRun` /
  `onLibraryChanged`）を維持する。**ウィンドウの UI ロジックは新設の
  `plugin/js/status-window.js`（`ME.statusWindow`）へ移し**、`main.js` の
  仮 UI 結線（`DOMContentLoaded` 内）を置き換える
- `onPluginRun` の起動時自動発火ガード（`isBootstrapping`）は現状のまま（coding.md 6.1）
- **起動時の IP 不在チェック（9 章）の担当・タイミング**: `main.js` の `onPluginCreate` による
  サーバー自動起動とは独立に、**status-window.js** が担う。`isBootstrapping` の猶予（3 秒）明け
  付近で IP 列挙のリトライ（4.3）を行い、`serverEnabled` かつ `selectedIp` が現存しなければ
  `eagle.window.show()` で再選択を促す（概要.md 71-72）
- **ウィンドウサイズ**: `manifest.json` の `main.width`/`height` を **520×660**（指示書）にする。
  `minWidth`/`minHeight` は下限として維持し、リサイズは Eagle 標準で可能

## 9. エッジケース・エラー処理

| ケース | 挙動 |
| --- | --- |
| ポート使用中（`EADDRINUSE`） | 重大エラー（4.6）。ウィンドウ表示 + `showMessageBox`。トグル/状態は実態に戻す |
| 保存ボタンでのポート再起動が途中で失敗 | 重大エラー（4.6）。状態を実態に合わせる |
| 外部 IP が 0 件（列挙前・Tailscale 未出現） | 数秒おきに数回リトライ。それでも 0 件なら"選択肢なし"表示。QR は非表示/空 |
| 起動時 ON かつ `selectedIp` が現存しない | リトライ後も無ければ `eagle.window.show()` でウィンドウを開き再選択を促す（概要.md 71-72） |
| IP 未選択で QR 生成 | QR を出さず、選択を促す状態にする |
| パスワードが制約違反（129 文字以上・許可外文字） | 保存しない。入力側で弾く（軽微。ログのみ） |
| サーバー停止中に QR のアクセス先が示される | 状態表示（4.5）で「停止中＝到達不可」を明示する |
| ライブラリ切り替え | ウィンドウの表示内容に影響なし（サーバー・設定は継続。backend/base.md 9 章） |
| Eagle 起動時の `onPluginRun` 自動発火 | ウィンドウを開かない（`isBootstrapping` ガード。coding.md 6.1） |

## 10. セキュリティ

- **パスワード・認証トークンを QR・ログ・画面の非マスク領域に出さない**（auth.md 4 章）。
  QR に載せるのはアクセス URL のみ
- パスワードの平文 localStorage 保存・`http`（非 TLS）通信は VPN 前提で許容（概要.md / auth.md 8 章）
- このウィンドウはローカル（Eagle レンダラー）でのみ開き、LAN には公開されない

## 11. スコープ外

- **認証ロジック本体**（トークン生成・Cookie 検証・localhost 免除・`/api/auth/*`）→ [backend/auth.md](auth.md)
- **フロントエンド側の認証ダイアログ・起動フロー** → frontend/auth.md
- **デザイン・レイアウト**（画面構成・配色・寸法・テーマ）→ 別途 Claude Design モックアップ
- ステータスウィンドウの多言語化（日本語固定）
- 選択 IP による**サーバーのバインド切り替え**（サーバーは常に `0.0.0.0`。selectedIp は QR 表示専用）
