# Mobile Eagle 概要

## プロジェクトの目的

画像管理アプリ「Eagle」をスマートフォンに最適化したUIで閲覧するための **Eagleプラグイン** を作る。

- プラグイン名：**Mobile Eagle**
- 過去に作成した「Simple Eagle」（`/Volumes/D/works/simple-eagle`）の移植
- Simple Eagle はCLIアプリ（Python必須・手動起動）で導入の敷居が高かったため、Eagleプラグイン方式にして敷居を下げる
- 外線からのアクセスは Tailscale などのVPNを利用することを前提とする

## 実現可能性の検討結果

**実現可能**（2026-07-09 調査済み）

- Eagleプラグインは Chromium 107 + Node.js 16 環境で動作し、Node.jsのネイティブAPI・npmモジュールが利用可能
  - → `http.createServer` や express でHTTPサーバーを起動できる
- manifest.json に `"serviceMode": true` を指定すると **バックグラウンドサービス型** になり、Eagle起動時に自動開始・ウィンドウなしで常駐できる
- ライブラリのデータは プラグインAPI（`eagle.item` / `eagle.folder` 等）で取得できる
  - itemオブジェクトが `filePath` / `thumbnailPath` / `tags` / `star` などを直接持つため、Web API（`localhost:41595`）を経由する必要がない
  - Simple Eagle でやっていた「サムネイルパスの文字列加工で元ファイルパスを推測する」ハックが不要になる

## アーキテクチャ

```
[Eagle 本体]
  └─ Mobile Eagle プラグイン（serviceMode: true / Eagle起動時に自動開始）
       ├─ HTTPサーバー（0.0.0.0:8000 で待ち受け）
       │    ├─ フロントエンド（SPA）の静的配信
       │    └─ API（eagle.item / eagle.folder でデータ取得して返す）
       └─ ステータスウィンドウ（普段は非表示 / プラグインクリックで表示）

[スマートフォン] ── LAN / VPN(Tailscale) ──> http://{PCのIP}:8000
```

- サーバーは `0.0.0.0` にバインドするため、PCが持つ全IPアドレス（LAN・Tailscale等）で同時に待ち受けになる
- QRコードは「どのIPのURLを表示するか」の選択のみ（サーバー側の切り替えは不要）
- ユーザーがプラグインパネルでプラグインをクリックすると、既存インスタンスの `onPluginRun` が発火するので、そこで `eagle.window.show()` を実行してステータスウィンドウを表示する（二重起動にはならない想定・要実機確認）

## ステータスウィンドウに表示する項目

| 種類 | 項目 | 備考 |
| --- | --- | --- |
| トグル | サーバーのON/OFF | 前回の状態を復元する。初回はON |
| 画像 | QRコード | アクセス用URLをQRコード化（初回アクセスを簡単にする） |
| ドロップダウン | QRコード切り替え候補のIPアドレス | `os.networkInterfaces()` で列挙。Tailscale（`100.64.0.0/10`）等をラベル付けして選択 |
| 数値 | ポート番号 | デフォルト `8000` |
| テキスト | ログインパスワード | 英数記号のみ 0〜128文字。空欄ならパスワードなし |
| テキストエリア | ログ | 直近200件を表示 |

## 設定の永続化

`localStorage` を使う（別プラグインで実装実績あり）。`serviceMode` のプラグインは Eagle 起動時にレンダラーごとロードされるため、`onPluginCreate` の時点で同期的に読み出せる（DOM構築を待つ必要がない）。

**永続化する項目**：

- サーバーのON/OFF
- ポート番号
- 選択したIPアドレス
- ログインパスワード（**平文で保存する**。VPN前提の個人用ツールのため許容する）

**ライブラリごとの設定分けは行わない**（設定はプラグイン単位で共有する）。

### 起動時の復元フロー

```
onPluginCreate
  ├─ localStorage から設定を読む（初回はデフォルト値）
  ├─ サーバーOFF → 何もしない（プラグインは常駐したまま。あとからウィンドウでONにできる）
  └─ サーバーON  → サーバーを起動
        └─ 保存済みのIPアドレスが os.networkInterfaces() に存在しないか？
              └─ Yes → eagle.window.show() でウィンドウを開き、エラーを表示してユーザーに選ばせる
```

**注意（実装時の考慮点）**：

- 選択IPは **QRコードの表示にしか使わない**。サーバーは `0.0.0.0` にバインドするので、保存したIPが無くてもサーバー自体は正常に動く
- **Tailscale の仮想インターフェース（`utun*`）は、OSログイン直後だと Eagle 起動時点でまだ現れていない可能性がある**。起動直後に1回だけ判定すると、実際には使えるのに「IPが存在しない」と誤検知してウィンドウが開いてしまう
  → 対策：IPが見つからない場合はすぐエラーにせず、数秒おきに数回リトライしてから判定する

## フロントエンド

- 基本的には **現行の Simple Eagle をそのまま使う**
- 構成：Vue 3 + TypeScript + Vite + Pinia + Tailwind CSS
- ビルド済み `dist/` をプラグインフォルダ内に配置し、HTTPサーバーから静的配信する
  - `.eagleplugin` にパッキングすると一緒にアーカイブされ、インストール後も配信できることを検証済み（T8）
  - 配信時は MIME タイプの判定と、ディレクトリトラバーサル対策（`dist/` の外は403で拒否）が必要

## バックエンド

- **現行の Simple Eagle に実装しているAPIを継承する**（Python + FastAPI → Node.js に書き直し）
- 継承するAPI：
  - 画像一覧の取得（フィルタ：keyword / ext / tags / orderBy / folders）
  - フォルダ一覧の取得
  - サムネイル配信
  - 画像配信（大きい画像はJPEG圧縮。Pillow の代替は Canvas API を想定 ※sharp はネイティブビルドの問題があるため避ける）
  - アイテム更新（⭐評価・タグ）
  - 削除（ゴミ箱へ移動・複数指定対応）
- サーバー側キャッシュ（圧縮画像のファイルキャッシュ）も継承する

## 認証

- ログインパスワード方式（ステータスウィンドウで設定。空欄ならパスワードなし）
- Eagle本体のWeb API（`localhost:41595`）が「localhostは認証免除・リモートはトークン必須」という方針なので、これを参考にする
- VPN前提のためリスクは限定的だが、プラグインとして配布する以上は必須級の機能

## エラー発生時の通知方法（検証済み・方針確定）

テストプラグインでの実機検証（2026-07-09）により、以下のとおり確定した。

| 方法 | 実機での挙動 |
| --- | --- |
| `alert()` | プラグインウィンドウが再出現し、その上にダイアログ表示。Eagle本体は操作可能 |
| `eagle.dialog.showMessageBox()` | `alert()` と同じ挙動。加えてタイトル・詳細文・ボタンを制御でき、非同期で扱える |
| `eagle.notification.show()` | OSトースト通知。数秒で自動消滅。ウィンドウは出現しない |

**方針**：

- **重大エラー**（ポート使用中でサーバー起動失敗など、機能が使えない）
  → `eagle.window.show()` でステータスウィンドウを表示し、画面内にエラーを表示。加えて `eagle.dialog.showMessageBox()` を出す
- **軽微なエラー**（個別リクエストの失敗など）
  → ログ（直近200件）に記録するのみ

`alert()` ではなく `showMessageBox()` を使う（挙動は同じで制御性が高いため）。

## 検証結果の要点（2026-07-09）

詳細は [specs/plugin-test.md](specs/plugin-test.md) を参照。

**確認できたこと**：

- ✅ **プラグイン内のHTTPサーバーにスマホから到達できる**（localhost / LAN / Tailscale すべて成功）。しかも **macOSのファイアウォール許可ダイアログが出ない**（Eagle本体のプロセス内で動くため）。ユーザーの追加操作が不要
- ✅ **`serviceMode: true` で Eagle 起動時に自動開始する**。プラグインをクリックしなくてもサーバーが立ち上がり `/ping` が応答した
- ✅ プラグイン動作中にクリックしても**二重起動されず**、`onPluginRun` が発火する。ウィンドウを閉じてもサービスは継続する
- ✅ **画像圧縮は `OffscreenCanvas` で十分**（4〜5MBの画像を 122〜169ms で約1/10に圧縮）。ネイティブモジュール（sharp）は不要。通常のCanvasより常に高速で出力は同一
- ✅ ピュアJSのnpmモジュール（`qrcode`）が `require()` でそのまま使える
- ✅ **フォルダ移動が可能**（`item.folders` を書き換えて `save()`）。Simple Eagle の不満点が1つ解消する
- ✅ ライブラリ切り替え後もサーバーは継続し、`eagle.item.get()` は新ライブラリを自動参照する
- ✅ **フロントエンド（HTML/CSS/JS）をプラグインに同梱して配信できる**。`.eagleplugin` にパッキングすると `public/` ごとアーカイブされ、インストール後もプラグインフォルダから読み出して配信できる（Tailscale 経由で表示を確認）

**制約として確定したこと**：

- ❌ **ゴミ箱内アイテムは取得できない**。ゴミ箱に661件ある状態でも取得0件、`isDeleted` は常に `false`、`get({isDeleted:true})` はパラメータ自体が無視される。Simple Eagle と同じ制約が残るため、**Mobile Eagle でもゴミ箱閲覧は実装しない**

**実装時の落とし穴（対策済み）**：

- ⚠️ **`onPluginRun` は Eagle 起動時にも自動発火する**（`onPluginCreate` の8ms後）。公式ドキュメントの「ユーザーがプラグインパネルでクリックしたとき」という記述は不正確。ここで無条件に `eagle.window.show()` を呼ぶと、**Eagle 起動のたびにウィンドウが勝手に開いてしまう**
  → **対策**：`onPluginCreate` からの経過時間（3秒）で「起動時の自動発火」と「ユーザーのクリック」を区別し、前者では `eagle.window.hide()` を呼ぶ。実機で検証済み（ウィンドウは開かず、一瞬のちらつきも発生しない）

**未解決の課題はなし。** 想定していた動作フロー（Eagle起動 → 自動常駐 → スマホからアクセス → 必要時のみウィンドウを開く）が実機で成立することを確認した。

## 実装時の留意点

- `onPluginRun` で `eagle.window.show()` を無条件に呼ばない（上記の自動発火対策）
- 画像圧縮は `OffscreenCanvas` を使う
- 画像の読み込みは `fetch()` が `file://` を扱えないため `fs.readFileSync(item.filePath)` → `Blob` → `createImageBitmap()` の経路を使う
- `eagle.item.get()` に `orderBy` / `limit` / `offset` は**存在しない**。並べ替え・件数制限はJS側で行う
- `eagle.item.get({})` は全件（数万件）を一度に返す。`fields` パラメータで返却フィールドを絞る最適化を検討する
- `onLibraryChanged` は Eagle 起動直後にも発火するため、初期化処理と二重にならないようガードする
- ライブラリ切り替え時はサーバー側のキャッシュ（圧縮画像）を破棄する
