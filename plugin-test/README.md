# Mobile Eagle Test

[plugin-test.md](../.claude/specs/plugin-test.md) の要検証事項（T1〜T7）を実機確認するためのテスト用 Eagle プラグイン。検証専用の使い捨てです。

## セットアップ

```sh
cd plugin-test
npm install
```

## Eagle への読み込み

1. Eagle を起動する
2. `P` キーでプラグインパネルを開く
3. 右上のメニューから「プラグインを開発」→「ローカルプロジェクトをインポート」を選び、この `plugin-test/` フォルダを指定する
4. Eagle を再起動する（`serviceMode: true` の自動起動を確認するため）

## テスト手順

### 事前準備

- ライブラリに `.webp` の画像を数枚入れておく（T5用）
- ゴミ箱に数件のアイテムを入れておく（T6用）
- 移動テスト用のフォルダを1つ作っておく（T6用）
- スマホに Tailscale を入れて同じネットワークに参加させておく（T3用）

### T1. ライフサイクル・二重起動確認

1. Eagle を再起動し、プラグインパネルからプラグインをクリックしてウィンドウを開く
2. ログに `onPluginCreate` が **Eagle起動時の時刻** で記録されていれば自動起動できている
3. ヘッダーの「インスタンスID」を控える
4. 「ウィンドウを隠す（hide）」を押す → プラグインパネルから再度クリック
5. インスタンスIDが変わらなければ **二重起動されていない**

### T2. 非表示中のダイアログ・通知の挙動

各ボタンを押すと10秒後に実行されます。押したらすぐウィンドウを隠して、何が起きるか観察してください。

- `alert()` … 非表示中に出るか？ ウィンドウが勝手に出てくるか？ 何も起きないか？
- `showMessageBox()` … 非表示中に出るか？
- `notification.show()` … OS通知が出るか？

### T3. HTTPサーバー・外部アクセス

1. プラグインは起動時に自動で `0.0.0.0:8000` にサーバーを立てます
2. 同一PCのブラウザで `http://localhost:8000/ping` を開く
3. スマホ（同一LAN）で `http://{LANのIP}:8000/ping` を開く
4. スマホ（Tailscale）で `http://{TailscaleのIP}:8000/ping` を開く
5. macOS のファイアウォール許可ダイアログが出たら、その文言を記録して許可する

IPアドレスは結果欄に一覧表示されます（Tailscale・LANのラベル付き）。

### T4. QRコード

「QRコード生成」を押し、表示されたQRコードをスマホで読み取ってページが開くか確認します。
IPアドレスはT3のドロップダウンで選んだものが使われます。
（開くのは T8 の静的配信ページです）

### T5. Canvas圧縮

「実行」を押すと、`.webp` をサイズ降順に取得して長辺2048px・JPEG品質85へ変換し、
1件ごとの処理時間（読込 / 通常Canvas / OffscreenCanvas）を計測します。
変換後の画像はサムネイル表示されるので、破綻していないか目視確認してください。

**目安**：4K級の画像1枚あたり1秒以内なら実用範囲。

### T6. ゴミ箱・フォルダ移動

- **ゴミ箱取得テスト**：ボタンを押すだけ。`eagle.item.get({})` / `getAll()` / `get({isDeleted:true})` の3通りで、ゴミ箱内アイテムが取れるかを調べます
- **フォルダ移動テスト**：先に **Eagle 本体側でアイテムを選択** してから、移動先フォルダを選んでボタンを押します。実行後、Eagle の表示でも移動しているか目視確認してください

### T7. ライブラリ切り替え

1. Eagle でライブラリを切り替える
2. ログに `onLibraryChanged` と新しいパスが出るか確認
3. 「切り替え後の動作確認」ボタンで `/ping` と `eagle.item.get()` が動くか確認

### T8. 静的ファイル配信

プラグインフォルダ内の `public/` を配信します。

1. 「配信元を確認」を押し、パス解決の結果（`eagle.plugin.path` / location由来 / `__dirname`由来）と、
   `index.html` `css/style.css` `js/app.js` がすべて ○ になっているか確認する
2. 「ブラウザで開く」でPC上の表示を確認する
3. スマホから `http://{IP}:{ポート}/` を開き、以下を確認する
   - **カウントアップボタンで数字が増える**（JavaScript が動いている）
   - **背景がグラデーションになっている**（CSS が効いている）
   - 「配信元の情報」に `/ping` の応答（JSON）が表示される（同一オリジンのAPI呼び出し）
4. 念のため `http://{IP}:{ポート}/../manifest.json` にアクセスし、**403 が返る**ことを確認する

**最後に `.eagleplugin` にパッキングしてインストールし直し、同じことができるか確認してください。**
プラグインパネルの右クリックメニュー →「Pack Plugin」でパッキングできます。

### エンドポイント一覧（テストプラグイン）

| パス | 内容 |
| --- | --- |
| `/` | `public/index.html`（カウントアップのテストページ） |
| `/css/*` `/js/*` | `public/` 配下の静的ファイル |
| `/ping` | JSON（サーバー稼働確認用） |
| `/hello` | 素のHTML（サーバー生成。静的配信を経由しない） |
